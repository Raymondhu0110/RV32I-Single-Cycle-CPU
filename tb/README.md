# Testbenches

This directory contains the Verilog testbenches used to verify individual RTL modules and the complete RV32I single-cycle processor.

The project uses Icarus Verilog for compilation and simulation, and GTKWave for waveform inspection.

## Build and Simulation

All commands below should be executed from the repository root directory, where `files.f` is located.

### Individual Module Test

The ALU testbench is used here as an example.

```powershell
# Check syntax and elaborate the ALU and its testbench.
iverilog -g2012 -tnull src/ALU.v tb/ALU_tb.v

# Compile the ALU testbench.
iverilog -g2012 -s alu_tb -o alu_sim src/ALU.v tb/ALU_tb.v

# Run the simulation.
vvp alu_sim

# Open the waveform generated by the testbench.
gtkwave alu_wave.vcd
```

Other module testbenches can be compiled and executed in the same way by specifying the corresponding RTL and testbench files.

### Complete CPU Integration Test

`files.f` lists the RTL source files required to compile the complete processor.

```powershell

# Check syntax and elaborate the complete CPU with the integration testbench.
iverilog -g2012 -tnull -s RV32I_top_tb -c files.f tb/RV32I_top_tb.v

# Compile the complete CPU with the integration testbench.
iverilog -g2012 -s RV32I_top_tb -o top_sim -c files.f tb/RV32I_top_tb.v

# Run the integration test.
vvp top_sim

```

This test uses the `top_imem_code.txt` and `top_dmem_code.txt` memory images.

### Final C Program Test

The final test executes a GCC-compiled bare-metal C program on the processor.

```powershell

# Check syntax and elaborate the complete CPU with the final testbench.
iverilog -g2012 -tnull -s RV32I_final_tb -c files.f tb/RV32I_final_tb.v

# Compile the complete CPU with the final testbench.
iverilog -g2012 -s RV32I_final_tb -o final_sim -c files.f tb/RV32I_final_tb.v

# Run the final test.
vvp final_sim

```

This test uses the `final_imem_code.txt` and `final_dmem_code.txt` memory images.

See [Programs](../programs/README.md) for the C program build process and [Memory Images](../memory/README.md) for the memory files used by each test.

## Working Directory

Run the simulation commands from the repository root directory. The memory initialization paths used by `$readmemb` are relative to the directory from which `vvp` is executed.
